# 成员 B · 卡滞力矩阈值与传感器噪声敏感性

实验日期为 2026-11-26。逐次结果、运行参数和十项源码/配置 SHA-256 见 [8.5 N·m 逐次数据](member-b-validation-threshold-sensitivity-r1/threshold-8.5.json) 与 [10.0 N·m 逐次数据](member-b-validation-threshold-sensitivity-r1/threshold-10.json)。每份数据包含 1,080 次运行，压缩轨迹按 JSON 的 meta.raw_directory 和 run_id 对应。

## 实验设计

沿用已有 validation 的 24 个单关节卡滞轨迹，覆盖 J0–J3、三个注入时刻和两组任务目标。检测阈值取 8.5、10.0 N·m。注入的合成卡滞力矩读数取 8、9、10、11 N·m，叠加标准差为 0、1.5、3 N·m 的高斯传感器噪声，每格使用随机种子 42。所有运行均启用在线信号滤波，并以容错关闭、V1、V2 三种策略运行。

无故障对照按场景、噪声档、随机种子和策略生成，每个阈值共 72 条对照，不随四个故障力矩读数重复。每个阈值包含 288 个故障条件与 72 个无故障条件，每个条件三种策略，共 1,080 次仿真。两阈值合计 2,160 次。故障读数和噪声为合成输入，仿真未使用实体传感器数据。

## 配对比较与解释边界

8.5 N·m 在本矩阵的故障检出数高于 10.0 N·m，差异集中在 8–10 N·m 的较弱读数。11 N·m 三档噪声下两个阈值均为 24/24 检出。对照场景的误报均为 0/72，但每档只有 24 个既有场景、三个噪声条件和一个随机种子，不能据此推断一般误报率。

8 N·m、零噪声时，8.5 N·m 也为 0/24 检出。该格的有噪声检出依赖读数越过阈值，且 1.5 N·m 噪声下平均延迟达 1.680 s。10.0 N·m 下，8–9 N·m 组也出现无检出或严重延迟。均值只统计检出的运行，未检出的运行不会进入延迟均值。V2 个别未检出场景仍通过末端位置评分，不能据此归因于检测或容错决策。

validation 场景曾用于此前实验，本矩阵属于仿真敏感性复核，不是独立盲测，也不代表真实机器人性能。结果支持保留 8.5 N·m 作为进一步评估的候选阈值，现有默认 10.0 N·m 配置未更改。做生产阈值选择仍需新的正常负载、阈值附近故障、传感器偏置/漂移和多个独立噪声种子数据。

## 复现

在仓库根目录运行：

~~~powershell
py edge/edge_node/test/benchmarks/run_threshold_sensitivity.py
py -m pytest -q edge/edge_node/test/test_threshold_sensitivity.py
py -m pytest -q edge/edge_node/test
~~~

运行入口在单个阈值内按噪声和种子生成匹配无故障对照，避免对四档故障力矩重复计入控制样本。完整配对规则由自动化测试覆盖。
