# 成员 B 实验失败模式分析

日期：2026-11-25
范围：未限速 pilot、限速算法复跑及预先冻结验证集的三策略仿真记录。验证集场景在运行前固定，但制定时已查看早期数据，因此不是独立盲测。恢复评分是轨迹物理结果，不能单独证明恢复由 V2 决策造成。

## 实验口径

- 开发集：24 个关节卡滞场景，每场景运行容错关闭、V1、V2 各一次。来源为 `docs/member-b-pilot.json`，原始轨迹目录为 `edge/edge_node/test/reports/task_recovery/member-b-validation-r2/`。
- 探索集：24 个不同目标场景，同样三策略配对。来源为 `docs/member-b-exploratory.json`，原始轨迹目录记录在其 `meta.raw_directory`。
- 限速复跑：V2 规划的健康关节目标采用 1.0 rad/s、2.0 rad/s² 限制，周期为 0.01 s。开发集结果见 `docs/member-b-limited-r3.json`，探索集诊断复跑见 `docs/member-b-limited-exploratory.json`。
- 预先冻结验证集：24 个场景，目标与开发/探索集不同，卡滞注入时刻为 0.40、0.80、1.20 s，场景种子标记为 300、301、302。当前仿真为确定性模型，不使用随机数。逐次结果见 `docs/member-b-validation-frozen-r1.json`，轨迹目录见其 `meta.raw_directory`。
- 恢复成功必须同时满足末端位置、保持时间、关节速度、关节力矩和卡滞关节负荷判据。规划器输出 `RECOVER` 单独不计成功。
- `NO_FEASIBLE_PLAN` 表示当前数值搜索未找到方案，不代表目标不可达的数学证明。

限速复跑随后修正了仿真卡滞观测模型。原模型冻结关节位置和速度，但没有产生符合卡滞条件的测量反作用力矩。现模型在卡滞期间将故障关节力矩传感器读数设为 12.5 N·m，不向被控对象施加该额外力矩。该读数高于检测阈值 10 N·m，且低于故障关节平均力矩评分上限 15 N·m。修正后开发集 V2 仍为 18/24 恢复、6/24 停稳，探索集 V2 为 19/24 恢复、5/24 停稳。此前限速复跑中 J2 未确认的三个样本，现均记录约 230–240 ms 故障确认延迟，并触发恢复。开发集 V1 从早期记录的 3/24 提升到 15/24，说明结果受卡滞观测模型影响。两批数据不可混作同一故障定义下的控制对照。探索目标已用于先前实验，两版探索结果都不是独立盲测。J3 仍有 1 个样本没有故障确认或恢复动作记录但达到轨迹位置评分，不能归因于算法决策。

## 合成卡滞力矩读数敏感性复核

在同一 validation 集执行 24 个基础场景 × 3 档读数 × 3 策略，共 216 次运行。每档均为容错关闭 11/24 恢复、V1 19/24 恢复、V2 21/24 恢复及 3/24 安全停稳。V1、V2 所有故障均确认，延迟均为 240 ms。V2 峰值关节速度为 0.999968 rad/s，STOP 后 0.04–0.22 s 进入停稳速度范围，随后满足持续保持判据。

三档读数均在检测阈值和评分上限之间，当前模型下的检测分支和恢复结果保持一致。该结果衡量人为指定的无噪声传感器读数变化对流程的影响，物理负荷变化和约束反力仍需单独建模。三档共享同一批目标和故障时刻，不增加独立基础场景数量。逐次记录、分档汇总及对应源码校验值已保存。[敏感性逐次数据](member-b-locktorque-sensitivity-r1.json)

## 限制

当前规划器只以末端位置误差检查恢复候选，不约束末端姿态。停止分支由当前搜索未找到解触发，因此报告应写“当前搜索范围和判据下未找到恢复方案后触发安全停止”。所有结果来自仿真。
