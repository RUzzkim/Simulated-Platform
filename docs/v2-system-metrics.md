# V2.0 系统指标分布（validation-r1）

## 0. 数据与口径

- 数据源：`edge/edge_node/test/experiments/data/official-validation-r1/summary.json`；共 72 条 Run，57600 帧原始轨迹。
- 每条 Run 目标时长 8.0s、采样率 100Hz，应有 800 帧。
- **控制周期**：相邻轨迹帧 `t_s` 之差，属于仿真时间周期，不是边端 OS/ROS 2 墙钟调度周期。
- **轨迹缺帧**：按 `step` 在应有区间内逐条核查，覆盖开头、中间和末尾缺失；缺帧率 = 缺帧数 / 应有帧数。它反映轨迹连续性，**不等同于 MQTT 网络丢包率**。
- **稳定性**：全程检查 `|q|≤3.14rad`、`|qd|≤1.96rad/s`、`|tau|≤50.00N·m`；另计算末 1 秒全部 6 关节速度 RMS。
- 周期分位数基于全部相邻帧间隔；峰值速度、峰值力矩和末 1 秒速度 RMS 先按 Run 计算，再对 Run 做 p50/p95/max 分布。分位数使用线性插值。

## 3. 结论与边界

- 72 条 Run 共 57600/57600 帧，轨迹缺帧 0，缺帧率 0.0000%。
- 仿真控制周期 p50=10.000ms、p95=10.000ms、max=10.000ms。
- 72/72 条 Run 全程满足位置、速度和力矩安全边界。
- 当前契约与回放负载没有应用层 `seq`，本数据不能识别 MQTT 重复、重传或网络丢包；真实网络丢包率需另加序号或由 broker/订阅端抓包统计。
